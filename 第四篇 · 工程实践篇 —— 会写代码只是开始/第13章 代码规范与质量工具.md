### 第13章 代码规范与质量工具：无聊是美德

> 📖 本章你将学会：
> - 理解Go"无聊是美德"的代码审美与Java"优雅是美德"的差异
> - 用gofmt/goimports/golangci-lint构建零争论的代码规范
> - 用Go的代码审查惯例替代Java的设计模式审查
> - 用`go generate`实现代码生成，替代Java的注解处理器

#### 13.1 代码规范：没有人争论格式

##### 13.1.1 开篇：Java的格式争论 vs Go的格式铁律

Java团队花多少时间争论代码格式？花括号换不换行？缩进2格还是4格？
`final`写不写？这些争论在Go世界**不存在**——因为`gofmt`。

```bash
# 一条命令格式化整个项目
gofmt -w .
# 或用goimports（自动管理import）
goimports -w .
```

`gofmt`是Go官方的格式化工具，它定义了唯一的代码格式——没有配置项，
没有选项，没有争论。所有Go代码长得一样。

> 💡 比喻：Java代码格式像西装——每个公司有自己的着装要求
>（checkstyle/spotless），员工各穿各的。Go代码格式像校服——
> 全国统一，没有人争论款式。

##### 13.1.2 Effective Go vs Effective Java

Java有《Effective Java》——90条最佳实践，讲的是"如何写出好的Java代码"。
Go有[Effective Go](https://go.dev/doc/effective_go)——讲的是"Go代码
应该长什么样"。

核心差异：Effective Java讲的是"设计决策"（何时用继承、何时用组合），
Effective Go讲的是"风格约定"（gofmt格式、命名惯例、golint规则）。

**Go命名惯例**：

| 概念 | Java惯例 | Go惯例 | 差异 |
|------|----------|--------|------|
| 公开类型 | `UserController` | `UserController` | 相同 |
| 私有类型 | `UserController` | `userController` | Go用大小写 |
| 方法名 | `getUserById` | `getUserByID` | Go缩写全大写 |
| 常量 | `MAX_CONNECTIONS` | `MaxConnections` | Go不用全大写 |
| 接口 | `Readable` | `Reader` | Go用-er后缀 |
| 包名 | `com.example.user` | `user` | Go简短小写 |
| 测试 | `UserTest` | `user_test.go` | Go用文件名 |

##### 13.1.3 Go代码审美：无聊是美德

```go
// Go风格: 简单直白
users := []User{{Name: "Alice"}, {Name: "Bob"}}
names := make([]string, 0, len(users))
for _, u := range users {
    names = append(names, u.Name)
}
```

```java
// Java风格: "优雅"的Stream
List<String> names = users.stream()
    .map(User::getName)
    .collect(Collectors.toList());
```

Go社区认为：**任何会编程的人都能一眼读懂for循环，但Stream需要
你熟悉Collectors和方法引用。** 在代码审查和紧急排障时，"无聊"
的代码胜过"聪明"的代码。

#### 13.2 静态检查与代码生成

##### 13.2.1 golangci-lint：一站式静态检查

```bash
# 安装
go install github.com/golangci/golangci-lint/cmd/golangci-lint@latest

# 运行
golangci-lint run
```

`golangci-lint`聚合了数十个linter，一条命令搞定所有检查：

| Linter | 检查内容 | Java对应 |
|------|------|------|
| `errcheck` | 未检查的error | 无（Java无error值） |
| `govet` | 常见错误 | SpotBugs |
| `staticcheck` | 静态分析 | FindBugs/SpotBugs |
| `unused` | 未使用的代码 | UCDetector |
| `gofmt` | 格式检查 | Spotless |
| `goimports` | import管理 | Import Order |
| `gocyclo` | 圈复杂度 | Checkstyle |
| `misspell` | 拼写错误 | SpellCheck |
| `revive` | 代码风格 | PMD |

##### 13.2.2 代码生成：go generate

Java用注解处理器（APT）在编译期生成代码——Lombok、MapStruct、
Dagger。Go用`go generate`+代码生成工具：

```go
//go:generate stringer -type=Pill

type Pill int

const (
    Placebo Pill = iota
    Aspirin
    Ibuprofen
    Paracetamol
)
```

```bash
go generate ./...
# 自动生成 pill_string.go，包含 String() 方法
```

| 维度 | Java APT | Go generate | 差异 |
|------|----------|-------------|------|
| 触发 | 编译时自动 | 手动`go generate` | Go显式 |
| 输出 | 修改字节码 | 生成.go文件 | Go可见 |
| 调试 | 难（魔法） | 易（看生成代码） | Go透明 |
| 常见工具 | Lombok/MapStruct | stringer/mockgen | 不同生态 |

#### ⚡ 13.3 性能贴士：工具链对开发效率的影响

**golangci-lint 实战配置**

```yaml
# .golangci.yml —— 项目级lint配置
linters:
  enable:
    - errcheck      # 检查未处理的error
    - govet         # 官方静态检查
    - staticcheck   # 综合静态分析
    - unused        # 未使用代码
    - gosimple      # 简化建议
    - gofmt         # 格式检查
    - goimports     # import排序
    - gocyclo       # 圈复杂度（阈值: 15）
    - misspell      # 拼写检查
    - revive        # 代码风格（PMD替代）

linters-settings:
  gocyclo:
    min-complexity: 15
  staticcheck:
    checks: ["all"]

issues:
  exclude-rules:
    - path: _test\.go
      linters:
        - gocyclo  # 测试文件允许高复杂度
```

**mockgen 代码生成实战**

Java 用 Mockito 在运行时动态生成 Mock 对象，Go 用 `mockgen` 在编译期
生成 Mock 代码——更透明、更类型安全：

```go
//go:generate mockgen -source=user_service.go -destination=mock_user_service.go -package=mock

// 接口定义
type UserService interface {
    GetUser(ctx context.Context, id int64) (*User, error)
    CreateUser(ctx context.Context, name, email string) (*User, error)
}

// 测试中使用生成的Mock
func TestHandler_GetUser(t *testing.T) {
    ctrl := gomock.NewController(t)
    defer ctrl.Finish()

    mockService := mock.NewMockUserService(ctrl)
    mockService.EXPECT().
        GetUser(gomock.Any(), int64(1)).
        Return(&User{ID: 1, Name: "Luis"}, nil)

    handler := NewHandler(mockService)
    // ... 测试handler逻辑
}
```

```bash
go generate ./...  # 生成所有mock文件
go test ./...      # 运行测试
```

对比Java的Mockito——Go的mockgen生成的是真实Go源码，你可以打开
`mock_user_service.go` 看到完整的Mock实现，而Mockito用字节码注入
在运行时动态生成，调试时是"黑盒"。

| 指标 | Java (Maven+Checkstyle+SpotBugs) | Go (go+golangci-lint) | 差异 |
|------|----------------------------------|----------------------|------|
| 格式化 | 需配置Spotless | `gofmt`零配置 | Go零争论 |
| 静态检查 | 需配置多插件 | `golangci-lint`一条 | Go一站 |
| 编译+检查 | 30-60s | 2-5s | 10-20x |
| CI流水线 | 多步骤 | 少步骤 | Go更简 |

> 💡 性能口诀：**gofmt铁律无争论，golangci-lint一站清；无聊代码
> 最可靠，聪明代码是陷阱。**

#### 本章小结

1. **gofmt消灭了格式争论** —— 唯一格式，零配置，全社区统一。
   Java需要Spotless/checkstyle且每个团队配置不同。

2. **Go审美是"无聊是美德"** —— for循环比Stream更可读，显式比隐式
   更可靠。Effective Go讲风格，Effective Java讲设计。

3. **golangci-lint一站式静态检查** —— 聚合数十个linter，一条命令。
   对标Java的SpotBugs+PMD+Checkstyle组合。

4. **go generate替代注解处理器** —— 显式触发、生成可见代码、
   可调试。比Java的APT更透明。

> 🤔 思考题：Go禁止了方法重载和运算符重载，这些"限制"是优势
> 还是劣势？当你写`a + b`时，Go保证就是加法，但C++可能调用了
> 一个自定义的`operator+`。哪种更好？
