#### 12.1 构建与交叉编译

##### 12.1.1 开篇：fat JAR vs 单二进制

Java部署的经典流程：`mvn package` → 得到一个80MB的fat JAR →
服务器装JDK → `java -jar app.jar`。JVM启动30秒后服务才就绪。

Go部署的经典流程：`go build` → 得到一个15MB的二进制 →
直接`./app` → 50毫秒后服务就绪。

这个差异在云原生时代被放大——Docker镜像大小、启动速度、内存占用
直接影响扩容速度和资源成本。

```bash
# Go交叉编译：一行命令
GOOS=linux GOARCH=amd64 go build -o myapp

# Java交叉编译：理论上"一次编写到处运行"，实际上...
# 需要确保服务器有正确版本的JDK，且JVM参数需要调优
```

##### 12.1.2 交叉编译对比

| 维度 | Java | Go | 差异 |
|------|------|----|------|
| 交叉编译 | 理论不需要（JVM抽象） | `GOOS=X GOARCH=Y`一行 | Go更直接 |
| 目标平台 | 需要对应版本JDK | 编译器内置所有平台 | Go零依赖 |
| 产物 | fat JAR（需JVM运行） | 静态二进制（直接运行） | Go自包含 |
| 体积 | 30-80MB（含依赖） | 5-15MB（`-ldflags`可更小） | Go小3-5x |
| CGO | N/A | 交叉编译需`CGO_ENABLED=0` | Go注意点 |

```bash
# Go二进制瘦身
go build -ldflags "-s -w" -o myapp # 去掉调试信息，减小~30%

# 构建所有平台
for os in linux darwin windows; do
    for arch in amd64 arm64; do
        GOOS=$os GOARCH=$arch go build -o myapp-$os-$arch
    done
done
```

#### 12.2 Docker容器化与配置管理

##### 12.2.1 Docker镜像对比

```dockerfile
# Java: 需要JRE基础镜像，镜像大
FROM eclipse-temurin:21-jre-alpine
COPY target/app.jar /app.jar
ENTRYPOINT ["java", "-jar", "/app.jar"]
# 镜像大小: ~200MB (JRE ~180MB + JAR ~80MB)

# Go: 多阶段构建，最终镜像极小
FROM golang:1.22 AS builder
WORKDIR /app
COPY . .
RUN CGO_ENABLED=0 go build -ldflags "-s -w" -o myapp

FROM scratch  # 空镜像！
COPY --from=builder /app/myapp /myapp
ENTRYPOINT ["/myapp"]
# 镜像大小: ~15MB (仅二进制)
```

| 指标 | Java镜像 | Go镜像(scratch) | 倍数 |
|------|----------|----------------|------|
| 镜像大小 | 200-400MB | 5-15MB | 15-30x |
| 拉取时间 | 10-30s | 1-3s | 10x |
| 启动时间 | 5-15s（JVM预热） | 0.05-0.2s | 100x |
| 内存占用 | 150-400MB | 10-30MB | 5-15x |

##### 12.2.2 配置管理：Spring vs Go

Java/Spring用`application.yml` + `@Value`注解：

```java
@Configuration
@ConfigurationProperties(prefix = "app")
public class AppConfig {
    @Value("${app.port:8080}")
    private int port;

    @Value("${app.database.url}")
    private String dbUrl;
}
```

Go用环境变量 + struct + 配置库：

```go
type Config struct {
    Port     int    `env:"PORT" default:"8080"`
    DBURL    string `env:"DB_URL" required:"true"`
    LogLevel string `env:"LOG_LEVEL" default:"info"`
}

func LoadConfig() (*Config, error) {
    cfg := &Config{}
    // 用envconfig或viper库解析
    return cfg, nil
}
```

Go的配置哲学：**12-Factor App——配置用环境变量。**
不写配置文件，不注解注入，用环境变量+struct tag。

> 💡 比喻：Spring配置像高级餐厅的固定菜单——厨师（Spring）按菜单
> 上菜，你点菜（改yml），厨师处理。Go配置像自助餐——你自己取
> 食材（环境变量），按自己的方式组合（struct），没有厨师。

##### 12.2.3 结构化日志：slog vs logback

Go 1.21+内建了`slog`包——结构化日志：

```go
import "log/slog"

func main() {
    logger := slog.New(slog.NewJSONHandler(os.Stdout, nil))

    logger.Info("user registered",
        "user_id", "123",
        "email", "alice@test.com",
    )
    // 输出: {"time":"2026-01-01T12:00:00Z","level":"INFO","msg":"user registered","user_id":"123","email":"alice@test.com"}
}
```

对比Java的logback/SLF4J——Go的`slog`更简洁，且内建于标准库。

#### ⚡ 12.3 性能贴士：二进制与启动优化

| 优化项 | 效果 | 命令 |
|------|------|------|
| 去掉调试信息 | 体积减30% | `-ldflags "-s -w"` |
| 禁用CGO | 静态链接，可scratch部署 | `CGO_ENABLED=0` |
| UPX压缩 | 体积减60%（有启动开销） | `upx --best myapp` |
| 预分配内存 | 减少启动时GC | 配置GOGC |

> 💡 性能口诀：**Go编译静态小，交叉编译一行搞；Docker用scratch，
> 十五兆就跑跑跑。**

#### 12.4 实战：多环境配置与结构化日志

##### 12.4.1 完整配置管理方案

实际项目中，配置来源通常有多个：环境变量、命令行参数、配置文件。
Go社区常用`viper`库统一管理，但更轻量的方案是`envconfig`+`flag`：

```go
package main

import (
    "flag"
    "fmt"
    "log/slog"
    "os"
    "strconv"
)

type Config struct {
    Env        string // dev / staging / prod
    Port       int
    DBUrl      string
    DBMaxConn  int
    LogLevel   string
    EnableAuth bool
}

func LoadConfig() (*Config, error) {
    cfg := &Config{}

    // 优先级：命令行参数 > 环境变量 > 默认值
    flag.StringVar(&cfg.Env, "env", getEnv("APP_ENV", "dev"), "运行环境")
    flag.IntVar(&cfg.Port, "port", getEnvInt("APP_PORT", 8080), "服务端口")
    flag.StringVar(&cfg.DBUrl, "db-url", getEnv("DB_URL", ""), "数据库地址")
    flag.IntVar(&cfg.DBMaxConn, "db-conn", getEnvInt("DB_MAX_CONN", 25), "数据库最大连接")
    flag.StringVar(&cfg.LogLevel, "log-level", getEnv("LOG_LEVEL", "info"), "日志级别")
    flag.BoolVar(&cfg.EnableAuth, "auth", getEnvBool("ENABLE_AUTH", true), "启用鉴权")
    flag.Parse()

    if cfg.DBUrl == "" {
        return nil, fmt.Errorf("DB_URL is required")
    }
    return cfg, nil
}

// 环境变量辅助函数
func getEnv(key, fallback string) string {
    if v := os.Getenv(key); v != "" {
        return v
    }
    return fallback
}
func getEnvInt(key string, fallback int) int {
    if v := os.Getenv(key); v != "" {
        if i, err := strconv.Atoi(v); err == nil {
            return i
        }
    }
    return fallback
}
func getEnvBool(key string, fallback bool) bool {
    if v := os.Getenv(key); v != "" {
        if b, err := strconv.ParseBool(v); err == nil {
            return b
        }
    }
    return fallback
}
```

##### 12.4.2 slog结构化日志实践

```go
func setupLogger(level string) *slog.Logger {
    var lvl slog.Level
    switch level {
    case "debug":
        lvl = slog.LevelDebug
    case "warn":
        lvl = slog.LevelWarn
    case "error":
        lvl = slog.LevelError
    default:
        lvl = slog.LevelInfo
    }

    handler := slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{Level: lvl})
    return slog.New(handler)
}

// 使用
func main() {
    cfg, err := LoadConfig()
    if err != nil {
        panic(err)
    }

    logger := setupLogger(cfg.LogLevel)
    logger.Info("server starting",
        "env", cfg.Env,
        "port", cfg.Port,
        "db_conn", cfg.DBMaxConn,
    )
    // 输出: {"time":"2026-01-01T12:00:00Z","level":"INFO","msg":"server starting","env":"dev","port":8080,"db_conn":25}
}
```

对比Java的Spring配置体系——Go没有`@ConfigurationProperties`自动绑定，
但手动解析更透明、更可控，且没有Spring的魔法层。

#### 本章小结

1. **Go交叉编译是降维打击** —— `GOOS=X GOARCH=Y go build`一行命令，
   编译出任意平台的独立二进制。Java需要目标平台的JDK。

2. **Go Docker镜像可以小到15MB** —— 多阶段构建+scratch基础镜像。
   Java镜像200-400MB（含JRE）。

3. **Go配置用环境变量** —— 12-Factor App哲学，不依赖配置文件和注解。
   用struct tag映射环境变量。

4. **slog内建结构化日志** —— Go 1.21+内置JSON日志，不需要logback。

> 🤔 思考题：Go二进制可以小到15MB，但Java的fat JAR有80MB。
> 体积差异从何而来？提示：JRE运行时 + 依赖库 + 对象头开销。
